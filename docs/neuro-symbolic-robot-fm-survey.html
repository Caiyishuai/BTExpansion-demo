1. 一句话结论

这个领域在 2022–2023 年问的是「大模型能不能当规划器」，2024–2025 年的答案是「能，但不可靠」，于是 2025–2026 年主流范式收敛为一句话：

把大模型从「规划器」降格/升格为「建模者（modeler）与提议者（proposer）」，把正确性交给确定性求解器，把失败交给符号层做可解释的修复。

换句话说，符号的角色从「被 LLM 替代的旧方法」变成了「LLM 的护栏、验证器和教练」。与此同时，符号层正在从任务层下探到运动/控制层（TAMP、动力学验证、代价函数设计），也正在内嵌进 VLA 模型本身（符号 primitive 接口）。

2. 分类框架：三条信息流 + 一个正交维度

我按符号与神经之间的信息流方向分类（与 IJCAI 2025 神经符号综述的三分法一致），再叠加一个正交维度：符号作用在系统栈的哪一层（任务层 / 运动层 / 架构内）。

类别信息流典型机制代表工作
A 符号→神经符号结构约束神经生成约束解码、PDDL 转移模型限解码、LTL 引导、SMT 校验、程序合成作为求解器SELP、SCLPlan、Code-as-Symbolic-Planner
B 神经→符号大模型产出/补全符号模型LLM 写 PDDL 域与问题、生成行为树、生成 3DSG 子图、从交互中归纳动作语义SayPlan、LLM-as-BT-Planner、LaMMA-P、PSALM-V、Gideon
C 双向闭环生成—验证—修复循环逻辑导师给出因果反馈、LTL critic、计划预执行校验、物理仿真回溯VIRF、LogicGuard、VerifyLLM、SENTINEL、Kinodynamic TAMP
D 架构内嵌可微/结构化符号层符号 primitive 指针、场景图神经符号层、LLM 设计代价函数、概率逻辑编程NS-VLA、CoRAL、NeuroStrata、Scallop 系
E 评估与反证—基准测试、消融、能耗与保真度度量PlanBench、PDDLStream 系统研究、"The Price Is Not Right"

3. A 类｜符号 → 大模型：用形式结构约束生成

核心思路：LLM 的自由度是问题也是资产。与其事后检查，不如在解码阶段就用符号结构把非法 token 屏蔽掉。

SELP: Generating Safe and Efficient Task Plans for Robot Agents with LLMs
ICRA 2025 · arXiv:2409.19471 · Purdue (Yi Wu, Lin Tan, Suresh Jagannathan)
  • 三件套：等价投票（采样多条 LTL 公式、按语义等价分组、取多数）、约束解码（用 LTL 约束自回归生成，保证计划满足规范）、领域微调（解 safety 与 efficiency 的目标冲突）。
  • 无人机导航：安全率 +10.8%、计划效率 +19.8%；机械臂操作：安全率 +20.4%。
  • 关键启示：把自然语言 → LTL 当成中间表示层，比直接 NL→动作序列可控得多。
SCLPlan: Constrained Natural Language Action Planning for Resilient Embodied Systems
JHU / ARL · arXiv:2510.06357 · 2025
  • 四阶段：LLM 把 NL + 3D 场景图翻译成 PDDL 目标态 → 调 Fast Downward 类求解器 → 失败则由 LLM 以 ReAct 方式给下一步 → 前置条件验证（PV）拦截非法动作并让求解器生成修正子计划。
  • ALFWorld 99%；真实 Spot 四足 10 个任务 100%（纯 LLM 50%、纯符号 30%）。
  • 消融：仅 PV 一步就在 7 个 LLM backbone 上平均 +40% 成功率；token 消耗比纯 LLM 每任务少约 2 万。
  • 值得注意的结论：「部分域（partial domain）就够了」——LLM 只需填补符号逻辑够不到的空缺。
Code-as-Symbolic-Planner: Foundation Model-Based Robot Planning via Symbolic Code Generation
IROS 2025 · arXiv:2503.01700 · (Yongchao Chen, Chuchu Fan, MIT)
  • 与 Code-as-Policies 的分野：代码不是用来调用机器人 API 的，而是让 LLM 现写一个 solver / planner / checker 来解带约束优化。
  • 7 个 TAMP 任务 × 3 个 LLM，相对最佳基线平均 +24.1% 成功率。
  • 意义：把「符号计算」这件事件本身外包给 LLM 的代码能力，绕开了预定义求解器泛化不足的问题。

同类还包括：用 PDDL 转移模型限制解码 + MCTS 评估可执行延续的神经符号具身智能体（VirtualHome / ALFWorld 上 4B–27B 模型成功率 >90%，token 更少）；以及 SELP 之前的 NL→LTL 系列工作。

4. B 类｜大模型 → 符号：让模型当建模者与规划器

这条线是「神经符号机器人」最早爆发的一支，也是和你自己工作（PDDL → 行为树）最直接相关的一支。

4.1 场景图作为符号接地层

SayPlan: Grounding LLMs using 3D Scene Graphs for Scalable Robot Task Planning
CoRL 2023 · QUT Centre for Robotics (Krishan Rana, Niko Sünderhauf)
  • 三招保证可扩展性：层次化语义搜索（对折叠 3DSG 做 expand/contract，只把任务相关子图喂给 LLM）、用 Dijkstra 接管导航序列缩短规划视野、场景图模拟器做迭代重规划。
  • 规模：3 层楼、36 房间、140 物体的真实移动操作机器人。
  • 后续 EmbodiedRAG（JHU/ARL, 2025）把 RAG 范式搬到 3DSG：检索任务相关子图并随执行动态调整，解决 token 上限与注意力偏置。

4.2 让 LLM 直接产出结构化控制器（行为树 / 层级树）

LLM-as-BT-Planner: Leveraging LLMs for Behavior Tree Generation in Robot Task Planning
arXiv:2409.10444 · 2024
  • 三层架构：LLM 组装规划器做任务分解 → LLM 行为树生成器产出完整 BT → 机器人接口加载执行并依据世界模型重规划。
  • 四种生成策略：一步生成 / 迭代生成（模拟器反馈自纠）/ 人机协作（用户反馈修正）/ 递归生成（MakePlan → MakeTree → PredictState 三次递归调用）。
  • 对小型 LLM 做了监督微调（单元树生成任务等）。
BT-ACTION / Interpretable Robot Control via Structured BTs and LLMs
arXiv:2504.02779 (KTH) · arXiv:2508.09621 (SnT) · 2025
  • BT-ACTION：测试驱动（test-driven）地让 LLM 生成 BT，45 人用户研究表明比直接 prompting 犯错更少、信任度更高、被试显著偏好。
  • 后者强调可解释 HRI，认知→执行准确率约 94%，代码开源。
MRBTP: Efficient Multi-Robot Behavior Tree Planning and Collaboration
AAAI 2025 · arXiv:2502.18072 · (Yishuai Cai 等，国防科大)
  • 多机器人 BT 规划，具备可靠性与完备性理论保证；跨树扩展协调异质动作；备份结构 + 意图共享处理同构冗余。
  • 可选 LLM 插件：用预训练 LLM 推理每个机器人的目标相关动作，预规划成长程子树，显著提速。
  • （这是你自己的组的工作，放在脉络里看：它属于「符号规划器为主 + LLM 做启发式加速」这一支，与下面 LaMMA-P / FLEET 的「LLM 为主 + 求解器兜底」恰好是镜像路线。）
Generalized Mission Planning for Heterogeneous Multi-Robot Teams via LLM-Constructed Hierarchical Trees
ICRA 2025 · Honda Research (Piyush Gupta 等)
  • LLM 不生成自由文本，而是调用受约束 API 构建 TAEMS 风格的层级任务树（AND / XOR / Precedence），从结构上抑制幻觉。
  • 再自底向上做启发式 MRTA 分配，带剪枝参数 ρ。5 个复杂场景中 4 个生成可行计划；在「推荐意大利餐厅」这一负例上正确判断出机器人能力不足。

4.3 LLM 驱动 PDDL 规划（多机器人）

LaMMA-P: Generalizable Multi-Agent Long-Horizon Task Allocation and Planning with LM-Driven PDDL Planner
ICRA 2025 · arXiv:2409.20560 · UC Riverside / Penn State
  • 六模块流水线：Precondition Identifier → Task Allocator → Problem Generator → PDDL Validator → Fast Downward / LLM Planner（失败回退）→ Sub-Plan Combiner。
  • 基准 MAT-THOR（AI2-THOR，5 个户型、70 个任务）。相对 SMART-LLM：成功率 +105%、效率 +36%。
FLEET: Formal Language-Grounded Scheduling for Heterogeneous Robot Teams
arXiv:2510.07417 · JHU/ARL · 2025
  • LLM 前端产出（i）带时长与偏序的任务图、（ii）能力感知的 robot–task 适配矩阵；MILP 后端解 makespan 最小化；执行层用 agentic 闭环控制。
  • 消融很有信息量：MILP 主要改善时间结构，LLM 给出的适配度对「能力耦合型」任务是决定性的——两者正交互补。
  • 真机：两台能力不相交的四足机器人。

4.4 从交互中归纳符号语义（解决「域从哪来」）

PSALM-V: Automating Symbolic Planning in Interactive Visual Environments with LLMs
arXiv:2506.20097 · USC (Ishika Singh, Jesse Thomason 等) · 2025
  • 不假设预定义问题文件、全可观或显式报错；通过分析执行结果 + 合成可能的错误解释来动态归纳 PDDL 问题文件与动作的 pre/post-condition，并维护树状信念。
  • ALFRED 部分可观测设置下：计划成功率从 37%（Claude-3.7）提升到 74%；RTFM、Overcooked-AI 上步长效率提升；真实机器人 BlocksWorld 上即便底层操作失败仍能正确归纳条件。
Gideon: Scalable Robot Autonomy via Neurosymbolic Planning with Lightweight Local LLM
IAS 2025 · arXiv:2505.08492 · Univ. of Genoa
  • 动机直击痛点：依赖 GPT 类闭源远程模型带来第三方依赖、响应抖动、计划长度与多域扩展受限。转而用本地小模型 + 长上下文。
  • 贡献了一个通用的 domain-problem-plan 三元组大规模数据生成器。
  • Qwen-2.5 1.5B（比基线小约 120×）：单域 32k 样本 66.1% 合法计划率，多域 16k 样本 70.6%——数据多样性正向影响学习效率。
OntoAct: Hypothesis-Based Neuro-Symbolic Agents through Ontological Abstraction
arXiv:2610.21983 · Seoul National University · 2026
  • 把经验提升为关于实体类型、关系与条件的公理（本体抽象），LLM 据此提出假设与动作，符号验证器核对支持条件；验证指出缺失证据，新观测再更新假设。
  • 配套基准 Tacit-FLE（基于 Factorio）：隐藏故障诊断与修复，证据分散在运行记录里，且修复可能不彻底、需要重新评估——比一次性规划更贴近现实。

5. C 类｜双向闭环：验证、批评与修复

2025–2026 年最活跃的方向。分歧点在于：符号层发现违规之后该做什么。早年是「拒绝 / 回退」，现在的共识是「给出可执行、可解释的修复信号」。

VIRF: Grounding Generative Planners in Verifiable Logic（Verifiable Iterative Refinement Framework）
ICLR 2026 · arXiv:2602.08373
  • 批评得非常准：现有安全范式让 LLM 监督 LLM（自我修正、多智能体辩论），是自指循环，无法给出可验证保证。
  • tutor–apprentice 对话：确定性的 Logic Tutor（锚定在形式安全本体上）给 LLM Apprentice 提供因果性、教学式反馈，让它「理解为什么不安全」从而修复而非回避。
  • 配套：从真实文档合成安全知识库的获取流水线（顺带暴露了现有 benchmark 的盲区）。
  • 结果：危险动作率 HAR 0%，目标条件率 GCR 77.3%（基线最高），平均仅需 1.1 轮修正。
LogicGuard: Improving Embodied LLM agents through Temporal Logic based Critics
arXiv:2507.03293 · 2025
  • actor–critic：LLM actor 选高层动作；critic 分析完整轨迹并提出新的 LTL 约束来「屏蔽」actor 未来的不安全/低效行为。支持固定安全规则与自适应学习约束，模型无关。
  • Behavior-100：Inner Monologue 47% → 72%；失败动作 23% → 4.5%。
VerifyLLM: LLM-Based Pre-Execution Task Plan Verification for Robots
arXiv:2507.05118 · 2025 · 附 ALFRED-LTL / VirtualHome-LTL 数据集
  • 用 LTL 作中间表示 + LLM 推理，系统识别三类计划不一致：位置错误、遗漏前置条件、冗余动作。
SENTINEL: A Multi-Level Formal Framework for Safety Evaluation of LLM-based Embodied Agents
arXiv:2510.12985 · Northwestern (Qi Zhu) 等 · 2025
  • 三层：语义层（NL 安全要求 → TL 公式，并探测 agent 理解是否对齐）、计划层（LTL 可满足性检查）、轨迹层（多轨迹合并为计算树，用 CTL 路径量词验证）。
  • 92% 安全约束成功翻译为语义等价的 LTL；计划层判定 35% 的计划不安全；轨迹层检出 87% 的安全违规。
Kinodynamic TAMP using VLM-guided and Interleaved Sampling
arXiv:2510.26139 · Ewha (Minseo Kwon, Young J. Kim) · 2025/2026
  • 混合状态树统一表示符号态与数值态，任务与运动决策共同进行；动力学约束交给运动规划器 + 物理仿真器验证（黑盒转移模型）；失败时 VLM 看渲染图预测回溯节点。
  • 相比 PDDLStream 与 LLM 类 TAMP：平均成功率提升 32%–1167%，复杂问题规划时间下降。双 UR5e 真机 n=3/4 达 100%。
Meta-Optimization and Program Search using Language Models for TAMP
CoRL 2025 · arXiv:2505.03725 · (Marc Toussaint 组)
  • 直指接口问题：既有方法不是抽象过度（链接简化技能原语）就是抽象不足（直接预测关节角）。做法是把轨迹优化问题的程序搜索当作基础模型与机器人控制之间的接口，并用零阶方法优化数值参数。

6. D 类｜架构内嵌：把符号层做进模型里

与前几类「LLM 在流水线外」不同，这一类是把符号结构变成模型内部的表示瓶颈。这是 2026 年最值得关注的新增量。

NS-VLA: Towards Neuro-Symbolic Vision-Language-Action Models
arXiv:2603.09542 · 2026 · 代码开源
  • 指出 VLA 的三个结构性问题：backbone 对结构盲目、泛化被 backbone 绑定、单层扁平目标优化。
  • 三件套：Neuro-Symbolic Encoder（计划约束的 primitive 推理）、Neuro-Symbolic Solver（骨干无关的策略，以当前 primitive 为条件）、分层联合策略优化（奖励粒度匹配）。
  • 接口从「图像+语言 → 连续动作」改为「→ 符号 primitive + 参数 → 动作块（action chunk）」。primitive 仍由神经策略选择，但高层输出是结构化的，因此可监督、可检查、可奖励、可调试。
  • 「单调指针（monotone pointer）」跟踪 primitive 序列进度，缩小搜索空间——这个设计对长程操作很关键。
CoRAL: 神经符号自适应循环（RSS 2026）
RSS 2026 · 复杂接触式操控
  • 不让 LLM 直接输出动作，而是让 LLM 当「代价设计师（Cost Designer）」，为底层 MPPI 运动规划器生成目标函数。
  • 神经符号自适应循环：VLM 先对质量、摩擦等物理参数做语义预估；执行失败时外层 LLM 依据物理反馈（如「推了没推动」）做在线系统辨识，实时修正物理参数认知并改写控制策略。
  • 检索式记忆单元存储成功的物理参数与接触策略，跨越冷启动。
  • 未见过的复杂接触任务（推拉、倚墙翻转、定力控制）上比 OpenVLA 等 SOTA 平均提升 50%+；真实 Franka Panda 上零样本部署。
NeuroStrata: Harnessing Neurosymbolic Paradigms for Improved Design, Testability, and Verifiability of Autonomous CPS
FSE 2025 (IVR) · arXiv:2502.12267 · Macquarie / UPenn / UF / Yale / Duke
  • 三层分层框架：高层纯符号（场景图 + 任务规划器）、中层神经符号（语义建图 + 局部规划）、底层神经符号（传感器融合 + 执行，施加物理/操作约束）。
  • Specification Mining：用 LLM 分析边缘案例数据（如事故日志）自动生成形式化安全规约；自上而下合成约束神经训练，自下而上通过程序归纳在运行时更新符号逻辑。
  • LASER 案例：目标关系预测 Recall@10 = 53.98%（+30.55% 于全监督基线）；分布外仅掉 0.52%。

同一脉络的其他工作：NEUROSYMLAND（概率场景图 + Scallop 规则执行，用于 UAV 着陆，强调可解释与可验证）；以及更传统的可微符号栈（DeepProbLog、NSCL、∂ILP、Logic Tensor Networks、Neural Logic Machines），它们在机器人上仍有生命力，但 2023 年后的增长点主要在「与基础模型结合」而非单独使用。

7. E 类｜冷静的评估与反证

这一类是最容易被忽略、但对判断方向最有价值的。它系统性地回答了「LLM 到底行不行」。

A Systematic Study of Large Language Models for Task and Motion Planning With PDDLStream

  • 任务：Robosuite 中 Franka Panda 解汉诺塔（每轮起始位置抖动约 1 cm）。三方对比：端到端 VLA（π₀ 级）、外部规划器逐步指令的 PG-VLA、神经符号模型 NSM。

9. 六条趋势判断

  1. LLM 的角色重新定位：从规划器 → 建模者 / 提议者。「让 LLM 直接吐动作序列」这条路线在 2025 年基本被证伪（执行保真度、几何细节反噬、能耗三重证据）。现在的主流是 LLM 负责 PDDL 建模、目标态生成、启发式剪枝、代价函数设计。
  2. 符号层的职责从「拒绝」升级为「解释 + 修复」。VIRF 的教学式因果反馈、LogicGuard 的约束生成、Kinodynamic TAMP 的 VLM 回溯——共同点是符号层不只说「不行」，而是说「为什么不行、往哪改」。
  3. 纵向：符号从任务层下探到运动与控制层。TAMP 的动力学验证、MPPI 代价函数设计（CoRAL）、VLA 内部符号 primitive 接口（NS-VLA）。「离散-连续可行性鸿沟」正在被当作核心问题而非工程细节。
  4. 横向：多机器人 / 异构团队成为主战场。LaMMA-P、FLEET、层级树任务规划、MRBTP——共同难题是能力感知的分配 + 时序协调 + 长程分解。LLM 的增量主要体现在「能力 ↔ 任务」的语义匹配上（FLEET 的消融直接证明了这一点）。
  5. 小模型 + 合成数据 + 本地部署是工程落地线。Gideon 用 1.5B 模型做到 66–70% 合法计划率，代价是大量合成数据；SCLPlan 每任务省 2 万 token。这一支和「能耗」论证（The Price Is Not Right）在指向同一个结论。
  6. 评估范式在换轴。从「成功率」扩展到：执行保真度、危险动作率（HAR）、目标条件率（GCR）、修正轮数、能耗、token 消耗、分布外鲁棒性。只会报成功率的论文越来越难站住。

仍未解决的开放问题

  • Symbol Grounding：符号谓词与真实感知之间的绑定仍是最大脆弱点；PSALM-V 式的「从执行结果反推语义」是目前最有希望的方向之一。
  • 开放世界的域归纳：如何不依赖专家手写域、在部分可观测与底层操作失败的情况下维护正确的动作模型。
  • 验证的可扩展性：高维连续状态空间上的形式验证代价仍然很高；NeuroStrata 明确把它列为首要障碍。
  • 可复现性：178 篇综述把 reproducibility 列为持续性挑战——prompt、模型版本、数据生成流水线的差异让跨论文比较困难。
  • 元认知缺失：agent 何时该知道自己不知道、何时该求助或切换策略，仅占文献 5%。

10. 结合 BT + PDDL 的选题建议

考虑到当前工作（PDDL → 行为树扩展、多机器人 BT 规划），以下几个缺口在文献里是明确存在的：

方向 1：LLM 生成 BT 的形式化保证（最直接的缺口）
  • 现状：LLM-as-BT-Planner 给出一步/迭代/人机协作/递归四种策略，但正确性靠模拟器反馈或人工；BT-ACTION 靠测试驱动与用户研究。
  • 缺口：BT 有明确的语义与成熟的可靠性/完备性理论（MRBTP 就用了），完全可以把 BT 转成时序逻辑公式或 SMT 约束做前置校验——用 SCLPlan 的 PV 思路或 VIRF 的 tutor 思路，但验证对象从「动作序列」换成「树结构」。
  • 卖点：BT 比线性计划更适合做形式化验证（反应式、带 fallback、可组合），这是 BT 相对 PDDL 计划序列的差异化优势，但目前没人把它讲成卖点。
方向 2：失败驱动的 BT 修复（对标 VIRF / LogicGuard）
  • 把 VIRF 的「逻辑导师给因果反馈」搬到 BT：执行失败时，符号层定位到具体条件节点/子树，给出「为什么这个 precondition 不成立」的解释，LLM 据此做局部修复而非整体重规划。
  • 可量化的指标很自然：修正轮数、修复后子树的复用率、局部 vs 全局重规划的 token/时间对比。
方向 3：多机器人 + BT + 能力感知分配
  • MRBTP 已有「LLM 预规划长程子树」的插件；FLEET 证明了 LLM 在能力耦合型分配上的决定性作用，两者可以直接缝合：LLM 做 robot–task 适配 → BT 跨树扩展做协调 → MILP/调度器处理时序。
  • 缺口：异构团队的 BT 目前缺统一的能力建模层，也缺公开的长程基准（MAT-THOR 是 PDDL 侧的，BT 侧没有对等物）。
方向 4：把「执行保真度 / 能耗」这套评估轴引进 BT 文献
  • 目前 BT + LLM 的论文基本只报成功率。援引 2507.23589 与 2602.19260 的方法论，做一份「BT 符号规划 vs LLM 直接规划」在执行保真度、修正成本、能耗上的对照评测，本身就是有引用价值的贡献。
方向 5：开放世界的 BT 条件归纳
  • PSALM-V 的思路（从执行结果 + 错误解释反推 pre/post-condition）迁到 BT 的条件节点上：BT 的执行轨迹天然带成功/失败/Running 三值信号，比线性计划提供更丰富的监督信号，这一点是 BT 独有的优势，值得写出来。
