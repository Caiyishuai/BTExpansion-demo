1项目介绍

btplan 是 BT Expansion 算法的一个清晰、可复现的工程实现。 它把"规划"和"执行"彻底分开：规划阶段只做集合运算、产出纯数据的行为树（IR）； 执行阶段把 IR 编译成 py_trees 节点，由 py_trees 决定每一拍走哪条分支。

自动建树

给 start / goal / actions，自动生成一棵可达目标的行为树，不需要手写控制流。

响应式

每拍都从根重新判断，外界把条件改了也能继续跑，而不是照着固定序列执行到底。

py_trees 驱动

运行时完全由 py_trees 的 Selector / Sequence 语义驱动，可无缝接入真实机器人。

PDDL 直入

支持标准 PDDL domain + problem，自动 grounding，并给出能否保证 Sound/Complete 的诊断。

易扩展

自定义条件 / 动作 / 环境，只需继承一个类或实现四个方法，规划侧零改动。

可验证

分层测试 + 随机问题基准（成功率 100%），重构与改动都有回归保护。

三个核心概念

理解这三个概念，就理解了整个项目：

概念含义例子
文字表示一个事实的字符串，是状态的最小单位At(b,ab)、Free(ab)
状态当前为真的文字集合。条件判断就是"集合包含"{Free(ab), At(b,pb)}
动作name / pre / add / del_set / cost，执行后 (state − del) ∪ addMove(b,ab)

最小示例

from btplan import Action, solve

actions = [
    Action("Move(b,ab)",
           pre={"Free(ab)"},                    # 前提：ab 位置空着
           add={"At(b,ab)"},                    # 做完：b 在 ab
           del_set={"Free(ab)", "At(b,pb)"}),   # 做完：ab 不空了、b 不在 pb
]

result = solve(start={"Free(ab)", "At(b,pb)"}, goal={"At(b,ab)"}, actions=actions)
print(result.summary())

3使用方法

三条使用路径：Python API（最灵活）、命令行（最快）、PDDL（最省事）。

3.1 Python API：四步

from btplan import Planner, SymbolicEnv, BehaviorTree, compile_tree, run, to_ptml

plan = Planner().plan(start, goal, actions)   # ① 规划：产出 IR 树（纯数据）
print(to_ptml(plan))                          #    顺手导出 PTML 文本

env  = SymbolicEnv(start, actions)            # ② 环境：状态的唯一持有者
bt   = BehaviorTree(compile_tree(plan))       # ③ 编译：IR → py_trees
bt.bind_env(env)

result = run(bt, env, goal=goal)              # ④ 运行：py_trees 驱动 tick
步骤入口作用
① 规划Planner().plan(start, goal, actions)纯符号反向扩展，返回 IR 树 BTNode
② 环境SymbolicEnv(start, actions)持有状态，提供 observe / apply / satisfies
③ 编译compile_tree(plan, library=None)IR → py_trees 节点树
④ 运行run(bt, env, goal=..., max_ticks=...)反复 bt.tick()，返回 RunResult
一键solve(start, goal, actions)上面四步的合成糖

RunResult 里有什么：

字段含义
success / status是否达成目标 / 根节点最后状态
ticks / costtick 次数 / 累计动作代价
actions实际执行过的动作名序列
trace / plan每拍节点状态文本 / 规划出的 IR 树

4从零写一个新任务（完整案例）

这一节从"我脑子里有个任务"走到"树图都画出来了"。跟着做一遍，你就掌握了一个新任务接入 btplan 的全部要点。 配套脚本：examples/05_new_task.py；同一任务也内置为 --domain ServeCoffee。

任务描述

机器人要把一杯咖啡送到餐桌上。拆解后有几层依赖——正是这些依赖让生成的树有分叉：

要达成先要什么
咖啡在餐桌上机器人在餐桌 且 手里有咖啡
机器人在餐桌门开着（才能走过去）
手里有咖啡机器人在咖啡机 且 手是空的
门开着手是空的（初始就成立）

① 设计文字

先把世界里的事实列出来。文字就是字符串，条件判断就是"集合包含"：

文字含义
At(Robot,Bar) / At(Robot,Machine) / At(Robot,Table)机器人所在的位置
HandEmpty手是空的
Holding(Coffee)手里拿着咖啡
DoorOpen门是开着的
On(Coffee,Table)咖啡在餐桌上

② 写 start：一开始什么是真的

start = {"At(Robot,Bar)", "HandEmpty"}

③ 写 goal：想让什么变成真的

goal = {"On(Coffee,Table)"}
目标是合取的：集合里所有文字都要成立，算法会把整个目标作为一个条件一起回溯。

④ 写 actions：每个动作的 pre / add / del_set

actions = [
    Action("Move(Robot,Machine)", pre={"DoorOpen"},
           add={"At(Robot,Machine)"}, del_set={"At(Robot,Bar)", "At(Robot,Table)"}, cost=1),
    Action("Move(Robot,Table)", pre={"DoorOpen"},
           add={"At(Robot,Table)"}, del_set={"At(Robot,Bar)", "At(Robot,Machine)"}, cost=1),
    Action("OpenDoor", pre={"HandEmpty"}, add={"DoorOpen"}, del_set=set(), cost=1),
    Action("BrewCoffee", pre={"At(Robot,Machine)", "HandEmpty"},
           add={"Holding(Coffee)"}, del_set={"HandEmpty"}, cost=2),
    Action("PlaceOnTable", pre={"At(Robot,Table)", "Holding(Coffee)"},
           add={"On(Coffee,Table)", "HandEmpty"}, del_set={"Holding(Coffee)"}, cost=1),
]
写动作的三个要点：
1. del_set 里一定要删掉同一谓词的其他取值（走到 Machine 就不再在 Bar / Table）， 否则状态会自相矛盾，树会走进死路。
2. 名字要唯一且可读——它既是动作标识，也是运行时节点的名字（Move(Robot,Table)）。
3. cost 目前只统计不参与搜索，写真实代价即可，将来换最优搜索直接受益。

两种语义：一步到位的动作在一次 tick 内做完并返回 SUCCESS，所以一拍可能连做几个动作； 分步（RUNNING）的动作一次 tick 只推进一步并返回 RUNNING，整棵树停在那里等下一拍—— 真实机器人（导航、机械臂）都是后者。

6核心算法

一句话：从目标出发反向扩展，直到这棵树能从初始状态跑起来。

三条判据

① 能产出 c 吗

c ∩ ((pre ∪ add) − del) ≠ ∅
且 c − del = c（不删 c 里的文字）

② 新前提是什么

c_attr = (pre ∪ c) − add
即"动作前提 + 还没达成的目标部分"

③ 要不要剪掉

若已扩展过的条件是 c_attr 的子集，说明这条路已被更宽的条件覆盖 → 剪掉

主循环

树 = 条件结点(goal)
while 树还不能从 start 跑起来:              # 符号求值 can_run()
    挑一个还没扩展过的条件结点 c            # 按长出顺序，广度优先
    if c != goal 且 c ⊆ start: break        # 已被初始状态满足
    for 每个"能产出 c"的动作 a:               # 三条判据
        挂一条分支：sequence{ cond c_attr, act a }
    把 c 原地"长成"：selector{ cond c, 上面那些分支 }

终止与失败

情况行为
树能从 start 跑起来正常返回
目标本来就被 start 满足不做扩展，返回单点树
所有条件都扩展完仍跑不起来抛 PlanningFailure（目标不可达）
规划期不看代价：扩展顺序就是动作列表顺序（FIFO），cost 只在运行时累计。 想做"优先扩展便宜动作"，把待扩展队列换成按累计代价排序的优先堆即可（MRBTP 的 MAOBTP 思路）。

五条关键约定

  1. 规划期不碰 py_trees。算法只在集合上做运算；py_trees 节点带父子指针与状态，不适合做"复制/替换"。
  2. IR 单向。只做 IR → py_trees、IR → PTML；不要反过来从 PTML 解析树。
  3. 控制节点固定 memory=False。每个 tick 从根重新评估，这是响应式与 Sound/Complete 的前提。
  4. 状态只在环境里。节点靠 bind_env 拿引用，自身不缓存状态。
  5. 文字统一用字符串。状态里的文字就是条件节点的名字，类型必须一致。

8用户自定义方法

三种扩展方式，按侵入性从低到高：自定义节点 → 行为库 → 自定义环境。

7.1 自定义 Condition / Action

继承 ConditionNode 或 ActionNode，只实现 update()。类名与文字同名即自动命中。

from btplan import ConditionNode, ActionNode, Status

class BeansLeft(ConditionNode):
    """条件：读环境的真实计数器，而不是查文字。"""
    def update(self) -> Status:
        return Status.SUCCESS if self.env.beans > 0 else Status.FAILURE

class Brew(ActionNode):
    """动作：两拍完成——第一拍预热（RUNNING），第二拍出咖啡。"""
    def initialise(self):
        self.heating = False          # 每次从非 RUNNING 进入时重置

    def update(self) -> Status:
        if not self.heating:
            self.heating = True
            return Status.RUNNING
        if self.env.beans <= 0:
            return Status.FAILURE
        self.env.apply(self.literal)   # 改符号状态
        self.env.beans -= 1            # 改环境自己的状态
        return Status.SUCCESS

注册进行为库

from btplan import BehaviorLibrary, BehaviorTree, Planner, compile_tree

library = BehaviorLibrary()
library.register(BeansLeft)     # 文字 "BeansLeft"    → 你的类
library.register(Brew)          # 文字 "Brew(Coffee)" → 你的类
# 也可以一整个目录：library.load_from_directory("my_domain")

plan = Planner().plan(start, goal, actions)
bt   = BehaviorTree(compile_tree(plan, library))   # ← 把库传给编译器
bt.bind_env(env)

7.2 自定义环境

实现 Environment 协议的四个方法即可，行为树那边一个字都不用改：

class Environment(Protocol):
    def observe(self) -> Iterable[str]: ...          # 当前为真的文字
    def satisfies(self, goal) -> bool: ...           # 目标是否达成
    def is_applicable(self, action_name) -> bool: ... # 前提是否成立
    def apply(self, action_name) -> None: ...        # 执行一步

# 例：在符号状态之外维护自己的计数器
class CoffeeShop(SymbolicEnv):
    def __init__(self, state, actions, beans=1):
        super().__init__(state, actions)
        self.beans = beans

7.3 冲突检测（剪掉物理上不可能的前提）

def conflict(premise) -> bool:          # 返回 True = 该前提不成立
    return "Holding(Coffee)" in premise and "Holding(Softdrink)" in premise

Planner(conflict_check=conflict).plan(start, goal, actions)

7.4 自定义节点速查

想做什么怎么做
读真实传感器继承 ConditionNode，update() 里读 self.env
多拍动作继承 ActionNode，未完成返回 RUNNING，initialise() 里重置状态
用参数Move("b","ab") → self.args = ("b","ab")，节点名 Move(b,ab)
